# 방 나가기와 말 모양 보정 설계

## 배경

현재의 결과 화면 `로비로 돌아가기`는 클라이언트 소켓만 끊어 서버 방에는 참가자 자리가 남는다. 이 때문에 대기실에서는 연결이 끊긴 자리가 시작을 막고, 진행 중인 게임에서는 영구 퇴장과 일시적인 연결 끊김을 구분할 수 없다. 또한 윷판 말 안에 닉네임 전체를 표시해 긴 이름을 가진 말이 타원형으로 늘어난다.

## 선택한 동작

첨부된 이전 작업 기록에서 사용자는 게임 중 퇴장 시 **남은 사람끼리 게임을 계속하는 방식**을 선택했다.

검토한 선택지는 다음과 같다.

1. 연결만 끊고 자리를 보존한다. 재접속에는 유리하지만 명시적인 `방 나가기`와 네트워크 단절의 차이가 없고, 유령 자리가 남는다.
2. 나가는 즉시 게임을 무효로 한다. 구현은 단순하지만 한 사람의 퇴장이 모든 참가자의 게임을 끝낸다.
3. 자리를 완전히 반납하고 남은 참가자가 계속한다. 명시적 퇴장과 일시 단절이 분리되고, 대기실과 진행 중 게임 모두 자연스럽게 정리된다.

3번을 적용한다.

## 서버 계약

- 인증된 참가자는 자기 자신에 대해서만 `LEAVE_ROOM` 명령을 보낼 수 있다.
- 명령은 `requestId`로 중복 실행을 방지한다.
- 사용자가 나가기로 결정한 사이 방 버전이 갱신돼도 퇴장이 실패해 자리가 남지 않도록, `LEAVE_ROOM`은 오래된 `roomVersion`을 허용한다.
- 일반 명령 제한을 이미 소진한 상태에서도 영구 퇴장은 처리돼야 한다. 퇴장 명령 자체는 한 번 성공하면 세션이 폐기되므로 일반 명령 횟수 제한에서 제외한다.
- 퇴장 시 참가자 자리, 재접속 토큰, 플레이어-방 연결, 개인/팀 색 점유를 제거한다.
- 방장이 나가면 접속 중인 남은 사람을 우선 새 방장으로 정한다.
- 마지막 참가자가 나가면 방을 빈 방으로 표시하고 기존 만료 정책으로 정리한다.

## 진행 중 게임 규칙

- 개인전에서는 나간 사람의 네 말을 제거한다.
- 팀전에서는 공용 말을 유지하고, 그 팀의 마지막 팀원이 나갈 때만 해당 팀의 말을 제거한다.
- 현재 차례인 사람이 나가면 보유 중인 던지기·말·경로 선택을 버리고 다음 참가자에게 새 차례를 준다.
- 현재 차례가 아닌 사람이 나가면 진행 중인 사람의 선택과 남은 제한 시간을 보존한다.
- 남은 조작 주체가 한 명 또는 한 팀이면 즉시 그 주체의 승리로 끝낸다. 아무도 남지 않으면 승자 없이 끝낸다.
- 퇴장 사실과 자동 승리 결과를 이벤트 기록에 남긴다.

## 게이트웨이와 클라이언트 흐름

1. 클라이언트는 현재 방 버전과 새 요청 ID로 `LEAVE_ROOM`을 전송한다.
2. 화면은 즉시 입장 로비로 전환하되, 패킷 유실을 피하려고 서버가 기존 소켓을 끊을 때까지 잠시 기다린다.
3. 서버는 방 상태를 갱신하고 남은 참가자에게 새 스냅숏을 보낸 뒤, 나간 참가자의 소켓을 강제로 해제한다.
4. 클라이언트는 저장된 재접속 토큰을 지우고 인증 정보가 없는 새 연결을 만든다.
5. 서버 응답이 없을 때는 제한 시간 뒤 로컬 연결을 정리하되, 정상 흐름은 서버의 퇴장 처리와 소켓 해제를 완료 조건으로 삼는다.

대기실과 종료 화면은 바로 나가며, 진행 중 화면은 내 말이 걷힌다는 확인창을 한 번 표시한다.

## 말 모양 보정

- 말 버튼의 너비와 높이를 같은 고정값으로 지정하고 넘치는 글자를 숨겨 항상 원형을 유지한다.
- 개인전 말에는 닉네임 앞 두 글자만 시각적으로 표시한다.
- 접근성 이름에는 전체 닉네임, 말 수, 위치 정보를 유지한다.
- 팀전 말은 기존처럼 팀 ID를 표시한다.

## 검증 범위

- 리듀서: 개인/팀 말 제거, 차례 이동, 진행 상태 보존, 자동 승리, 빈 게임, 이벤트 ID 단조 증가.
- 방 서비스: 자리·색·토큰 반납, 방장 위임, 진행 중 퇴장, 타이머 보존/재설정, 오래된 버전, 빈 방 정리.
- 게이트웨이: 남은 사람에게 스냅숏 전달, 퇴장 소켓 해제, 폐기 토큰 재접속 거절, 명령 제한 소진 후 퇴장.
- 클라이언트/UI: 서버에 명령이 실제 도착한 뒤 로비 전환, 대기실 버튼, 게임 중 확인창, 종료 화면 퇴장, 말 원형/접근성 레이블.
- 전체 타입 검사, 단위·통합·UI 테스트, 린트, 프론트/백엔드 빌드와 실제 브라우저 핵심 흐름을 회귀 검증한다.
