# 온라인 멀티플레이 윷놀이 설계

## 1. 목표와 범위

브라우저에서 방 코드와 닉네임만으로 참여하는 실시간 윷놀이 게임을 만든다. 계정 가입 없이 개인전과 8인 팀전을 지원하고, 게임의 모든 판정은 서버가 담당한다.

### 포함 범위

- 2~4인 개인전
- 4개 팀이 겨루는 8인 팀전(2명씩 4팀)
- 6자리 방 코드 기반의 방 생성과 참여
- 대기실, 준비 상태, 방장 권한, 팀 배치
- 실시간 턴 동기화와 새로고침 후 재접속
- 일반적인 윷놀이 규칙: 추가 던지기, 업기, 잡기, 빽도, 갈림길
- 데스크톱과 모바일 반응형 화면
- 이모지 반응과 게임 이벤트 기록

### 제외 범위

- 회원가입과 로그인
- 영구 전적 및 랭킹
- 자유 입력 채팅, 신고, 차단
- 관전자 모드와 게임 중 신규 참가
- 컴퓨터 상대 모드

## 2. 핵심 사용자 흐름

1. 사용자는 닉네임을 입력하고 개인전 또는 8인 팀전을 선택해 방을 만든다.
2. 서버가 발급한 6자리 방 코드를 다른 참가자에게 공유한다.
3. 참가자는 닉네임과 방 코드를 입력해 대기실에 들어온다.
4. 대기실에서 개인전은 2~4명, 팀전은 정확히 8명이 준비한다.
5. 방장은 참가자를 내보내거나 팀원을 재배치하고 게임을 시작한다.
6. 참가자는 자신의 차례에 윷을 던지고 이동할 말과, 필요한 경우 경로를 선택한다.
7. 서버가 결과를 판정해 모든 참가자에게 동일한 상태와 이벤트 기록을 전송한다.
8. 개인 또는 팀의 공용 말 4개가 모두 완주하면 게임이 종료된다.

## 3. 아키텍처

### 3.1 서버 권위형 실시간 구조

서버는 방 상태, 참가자 세션, 턴, 윷 결과, 말 위치, 경로, 추가 던지기, 승패를 관리하는 유일한 권위자다. 브라우저는 행동 의도를 WebSocket으로 보내고 서버가 반환한 상태만 표시한다. 클라이언트가 보낸 윷 결과나 이동 후 좌표는 신뢰하지 않는다.

클라이언트가 보내는 주요 명령은 다음으로 제한한다.

- 방 생성 및 참여
- 준비 상태 변경
- 방장에 의한 참가자 퇴장 및 팀 재배치
- 윷 던지기 요청
- 이동할 말 선택
- 갈림길 경로 선택
- 이모지 반응

서버는 모든 유효한 명령 처리 후 증가한 방 버전과 전체 공개 상태를 방의 모든 연결에 전송한다. 각 명령에는 클라이언트가 마지막으로 확인한 방 버전과 요청 식별자를 포함한다. 서버는 오래된 버전, 중복 요청, 잘못된 차례의 요청을 거부해 이중 진행을 막는다.

### 3.2 모듈 경계

- **방 관리:** 방 코드 발급, 참가·퇴장, 방장, 준비 상태, 팀 배치, 방 수명 관리
- **세션 관리:** 재접속 토큰, 연결 상태, 닉네임 중복 검사, 플레이어 자리 복원
- **게임 상태 머신:** 대기실·진행 중·종료 상태와 턴 단계 전환
- **윷 생성기:** 실제 윷가락 네 개의 앞·뒤 조합에 따른 결과와 빽도 판정
- **윷판 그래프:** 외곽 및 지름길의 노드, 전진·후진 경로, 갈림길 선택지 계산
- **말 규칙:** 출발, 이동, 업기, 잡기, 완주, 묶음 상태 계산
- **실시간 게이트웨이:** 명령 검증, 방 브로드캐스트, 오류 응답, 타이머 처리
- **웹 클라이언트:** 로비, 대기실, 윷판, 참가자 현황, 행동 패널, 이벤트 기록

게임 규칙과 윷판 계산은 네트워크 및 화면 코드에 의존하지 않는 순수 함수 중심으로 구성한다.

## 4. 게임 모드

### 4.1 개인전

- 참가 인원은 2~4명이다.
- 각 참가자는 자신의 말 4개를 가진다.
- 대기실 입장 순서를 기본 턴 순서로 사용한다.
- 자신의 말 4개를 가장 먼저 완주한 참가자가 승리한다.

### 4.2 8인 팀전

- 총 8명이 A, B, C, D 네 팀에 2명씩 배치된다.
- 각 팀은 공용 말 4개를 사용한다.
- 기본 턴 순서는 `A1 → B1 → C1 → D1 → A2 → B2 → C2 → D2`다.
- 추가 던지기와 그에 따른 이동을 모두 끝낸 뒤 다음 참가자에게 넘어간다.
- 팀 공용 말 4개를 가장 먼저 완주한 팀이 승리한다.

## 5. 윷놀이 규칙

### 5.1 윷 결과와 이동

윷가락 네 개의 앞·뒤를 독립적으로 생성해 결과를 결정한다.

- 빽도: -1칸
- 도: 1칸
- 개: 2칸
- 걸: 3칸
- 윷: 4칸
- 모: 5칸

빽도 표식은 네 윷가락 중 지정된 한 개에만 존재한다. 앞면 하나가 나온 도 조합에서 해당 윷가락만 앞면일 때 빽도가 된다.

### 5.2 턴 흐름

한 턴은 다음 단계를 반복한다.

1. `던지기 대기`: 현재 참가자가 윷 던지기를 요청한다.
2. `말 선택`: 서버가 계산한 합법적인 말 중 하나를 선택한다.
3. `경로 선택`: 선택한 이동에 갈림길이 있으면 가능한 경로를 하나 선택한다.
4. `이동 처리`: 업기, 잡기, 완주를 서버가 한 번에 판정한다.
5. `보너스 또는 종료`: 추가 던지기가 있으면 1단계로 돌아가고, 없으면 다음 참가자로 넘어간다.

윷 또는 모가 나오면 추가 던지기 1회를 얻는다. 상대 말을 잡아도 추가 던지기 1회를 얻는다. 한 번의 이동에서 두 조건을 모두 만족하면 총 2회의 추가 던지기를 얻으며, 획득한 기회는 현재 참가자가 연속으로 사용한다.

### 5.3 업기, 잡기, 완주

- 같은 개인 또는 같은 팀의 말이 같은 칸에 도착하면 하나의 묶음이 된다.
- 묶음은 이후 하나의 말처럼 이동한다.
- 상대 말이 있는 칸에 도착하면 상대 묶음 전체를 잡아 출발 대기 상태로 되돌린다.
- 완주 지점을 통과하는 데 필요한 이동 수가 충분하면 해당 말 또는 묶음 전체가 완주한다.
- 개인전에서는 자기 말끼리, 팀전에서는 같은 팀의 공용 말끼리만 업을 수 있다.

### 5.4 갈림길과 빽도

- 전진 이동이 갈림길에서 시작될 때 가능한 경로를 화면에 강조하고 플레이어가 선택한다.
- 이미 지름길에 들어간 말은 그 지름길의 연결을 따라 이동한다.
- 빽도는 판 위에 있는 말 또는 묶음만 한 칸 뒤로 이동한다.
- 빽도 시 여러 후진 경로가 가능하면 플레이어가 경로를 선택한다.
- 판 위에 이동 가능한 말이 없으면 빽도 행동은 소진되며, 남은 추가 기회가 없으면 턴이 끝난다.

## 6. 방과 세션 수명

- 방 코드는 혼동하기 쉬운 문자를 제외한 대문자와 숫자 6자리로 생성한다.
- 닉네임은 공백을 정리한 2~12자이며, 같은 방 안에서 대소문자를 무시하고 중복될 수 없다.
- 참여 시 브라우저에 추측하기 어려운 재접속 토큰을 저장한다.
- 새로고침 또는 일시적인 연결 끊김 후 같은 토큰으로 기존 자리에 복귀하고 즉시 최신 전체 상태를 받는다.
- 게임 시작 후 자리는 새로운 참가자로 교체할 수 없다.
- 모든 참가자가 나간 방과 종료된 방은 정리 유예 시간 후 메모리에서 삭제한다.
- 첫 버전은 서버 재시작을 넘는 영구 복구를 보장하지 않는다.

## 7. 시간 제한과 자동 진행

- 플레이어가 해야 하는 각 행동에는 45초 제한을 둔다.
- 제한 시간이 지나거나 해당 플레이어의 연결이 끊겨 있으면 서버가 행동을 자동 수행한다.
- 자동 윷 던지기는 정상 확률 생성기를 사용한다.
- 자동 말·경로 선택은 서버가 계산한 합법적인 선택지 중 하나를 균등하게 선택한다.
- 타이머 시작 시각과 만료 시각은 서버가 관리하고 클라이언트에는 남은 시간을 표시하기 위한 만료 시각만 전달한다.
- 재접속은 진행 중인 타이머를 초기화하지 않는다.

## 8. 사용자 인터페이스

### 8.1 시각 방향

한지색 바탕, 먹색 선, 단청에서 가져온 청록·주홍·황금색을 사용해 현대적이고 따뜻한 한국 전통 분위기를 만든다. 색상만으로 팀이나 상태를 구분하지 않고 문자, 문양, 외곽선도 함께 사용한다.

### 8.2 주요 화면

- **로비:** 닉네임, 방 만들기, 모드 선택, 방 코드 입장
- **대기실:** 참가자, 팀, 준비 상태, 방 코드 복사, 방장 도구, 시작 버튼
- **게임:** 중앙 윷판, 현재 차례와 남은 시간, 참가자·팀 현황, 윷 던지기 및 이동 선택, 이벤트 기록, 이모지 반응
- **결과:** 승자, 완주 순서, 다시 로비로 이동

데스크톱에서는 윷판을 중심으로 현황과 기록을 좌우에 배치한다. 모바일에서는 윷판과 행동 영역을 우선 표시하고 현황 및 기록은 접을 수 있는 패널로 제공한다.

### 8.3 접근성 및 입력

- 모든 핵심 행동에 명시적인 텍스트 레이블을 제공한다.
- 키보드로 윷 던지기, 말 선택, 경로 선택, 대화상자 닫기가 가능해야 한다.
- 현재 포커스를 분명하게 표시한다.
- 윷 결과와 잡기·업기·완주를 애니메이션뿐 아니라 텍스트 이벤트로 알린다.
- 동작 감소 설정을 존중한다.

## 9. 오류 처리와 권한

- 방 코드 오류, 인원 초과, 중복 닉네임, 시작 조건 미충족은 사용자가 해결할 수 있는 짧은 메시지로 안내한다.
- 게임 중 잘못된 차례, 오래된 버전, 중복 요청, 불가능한 이동은 상태를 바꾸지 않고 요청자에게 오류를 반환한다.
- 방장 권한은 대기실의 참가자 퇴장, 팀 재배치, 게임 시작으로 제한한다.
- 게임 시작 후 임의 퇴장은 허용하지만 자리는 재접속 가능 상태로 남기고 자동 진행을 적용한다.
- 예기치 않은 서버 오류가 발생하면 클라이언트는 마지막 상태를 유지하고 재동기화를 요청한다.

## 10. 검증 전략

### 10.1 단위 테스트

- 윷 결과 조합과 빽도 확률 분기
- 외곽, 중앙 지름길, 합류점, 완주를 포함한 모든 경로
- 갈림길의 전진 및 후진 선택지
- 단일 말과 묶음의 업기, 잡기, 출발 복귀, 완주
- 추가 던지기 0회, 1회, 2회 이상 누적
- 개인전과 팀전의 턴 순환 및 승리 조건
- 방 코드, 닉네임, 방 인원, 방장 권한 검증

### 10.2 상태 머신 및 통합 테스트

- 대기실에서 올바른 인원과 준비 상태일 때만 시작
- 잘못된 차례, 중복 요청 식별자, 오래된 방 버전 거부
- 재접속 토큰으로 자리 복원 및 최신 상태 수신
- 연결이 끊긴 플레이어의 제한 시간 만료와 자동 행동
- 게임 종료 후 추가 명령 거부

### 10.3 브라우저 흐름 검증

- 여러 브라우저에서 방 생성, 참여, 준비, 시작, 승리까지 수행
- 2~4인 개인전과 8인 팀전의 실시간 동기화
- 새로고침 및 연결 복구
- 데스크톱과 모바일 화면 배치
- 마우스, 터치, 키보드 입력

## 11. 완료 기준

- 2~4인 개인전과 정확히 8명이 참여하는 4팀 팀전을 방 코드로 시작할 수 있다.
- 모든 게임 판정이 서버에서 이루어지고 참가자 화면이 같은 상태로 유지된다.
- 합의한 일반 규칙, 추가 던지기, 업기, 잡기, 빽도, 지름길, 완주가 동작한다.
- 끊긴 참가자가 재접속 토큰으로 복귀하며, 미복귀 상태에서도 시간 제한으로 게임이 계속된다.
- 주요 규칙과 실시간 흐름에 자동 테스트가 있고, 여러 브라우저의 전체 흐름이 검증된다.
- 데스크톱과 모바일에서 핵심 조작이 가능하고 키보드 접근성을 제공한다.
