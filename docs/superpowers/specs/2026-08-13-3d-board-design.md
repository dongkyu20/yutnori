# 3D 윷판과 말, 그리고 잡기 연출 설계

## 1. 목표와 범위

윷판과 말을 three.js로 그려 판 위에서 벌어지는 일이 눈에 보이게 한다. 말은 칸을 하나하나 밟아 움직이고, 상대 말을 잡으면 충격파와 함께 튕겨 나가 자기 출발자리로 돌아간다.

### 포함 범위

- 윷판 바탕, 길, 29칸, 출발점과 지름길 길목 강조를 3D로 그린다.
- 판 위의 말을 3D 조약돌로 그린다.
- 말이 지나간 칸을 순서대로 밟아 이동한다. 빽도는 거꾸로 밟는다.
- 상대 말을 잡을 때 충격파 고리와 튕겨내기 연출을 재생한다.
- WebGL이 없거나 컨텍스트를 잃으면 지금의 2D 판으로 되돌아간다.
- 움직임을 줄이는 설정에서는 연출 없이 결과 자리로 바로 놓는다.

### 제외 범위

- 카메라 회전과 확대 조작
- 외부 모델 파일과 이미지 텍스처(텍스처는 캔버스로 직접 그린다)
- 소리
- 던지기 연출 변경(윷가락은 이미 3D이며 이 작업에서 건드리지 않는다)
- 관전 시점, 리플레이

## 2. 결정 사항

세 가지를 미리 정했다.

1. **3D는 보이는 것만, 조작은 DOM이 그대로 맡는다.** 이미 `YutSticks`가 쓰는 방식이다.
2. **정사 투영으로 판을 바로 내려다본다.** 지금의 퍼센트 좌표가 그대로 화면 좌표가 되어 DOM 겹침에 오차가 없다.
3. **잡기는 확 튕겨내기.** 잡힌 말이 어디로 가는지를 움직임이 그대로 알려 준다.

## 3. 레이어 구조

| 3D 캔버스가 그리는 것 | DOM이 계속 맡는 것 |
| --- | --- |
| 판 바탕과 테두리, 길(음각), 29칸 | 말 버튼: 클릭, 키보드, `aria-label` |
| 출발점 고리와 진행 방향 살촉, 길목 고리와 겹살촉, 방 | 경로 선택 버튼 |
| 3D 말과 그림자 | 칸의 이름과 역할 라벨 |
| 이동과 잡기 연출 | 말 개수 글자(`×2`)와 편 이름 |

캔버스는 `.yut-board__track` 안에 깔리고, 지금의 노드·말·경로 DOM이 그 위에 겹친다. three가 무대를 세우면 트랙에 `yut-board--3d`가 붙고, 그때만 2D 칸 그림과 말 바탕이 투명해진다. 클래스가 붙지 않으면 지금 화면과 완전히 같다.

이 구조 덕분에 jsdom(WebGL 없음)에서 도는 기존 보드 테스트 10개는 2D 경로를 그대로 검증한다. 3D를 켜고 끄는 것이 클래스 하나이므로 회귀 위험이 좁다.

### 3.1 좌표가 어긋나지 않는 이유

정사 투영으로 판을 수직으로 내려다보면 월드의 XZ 평면에서 화면으로 가는 사상은 아핀 변환이며, 절두체를 판 크기에 정확히 맞추면 항등 사상이 된다. 칸의 퍼센트 좌표 `(px, py)`는 월드 `((px - 50)/100 · S, 0, (py - 50)/100 · S)`에 놓이고, 화면에서 다시 같은 퍼센트 위치로 돌아온다. 트랙이 `aspect-ratio: 1`이라 절두체도 정사각이다. 따라서 DOM 버튼은 위치 계산을 하나도 바꾸지 않는다.

### 3.2 이 시점에서 포기하는 것

수직으로 내려다보면 원근이 없으므로 **말을 여러 개 쌓아도 실루엣이 하나와 같다**. 그래서 업기 개수는 3D 형상이 아니라 지금처럼 DOM 글자(`×2`)로 읽힌다. 입체감은 조약돌의 둥근 음영, 판에 지는 그림자, 그리고 움직임에서 나온다.

같은 이유로 **위아래 움직임도 화면에서는 자리를 바꾸지 못한다**. 정사 투영에서 높이는 화면 좌표에 들어가지 않으며, 이는 3.1의 항등 사상과 한 몸이라 하나만 골라 가질 수 없다(`boardScene.test.ts`가 "높이가 달라져도 화면 자리는 같다"를 아예 규칙으로 못박아 둔다). 그래서 밟아 갈 때의 뜀과 튕겨낼 때의 떠오름은 그림자가 커졌다 작아지는 것으로만 보인다. 위로 뜨는 느낌이 필요한 연출은 높이 대신 판을 따라 미끄러지는 거리와 크기 변화로 말해야 한다. 잡힌 말이 화면 아래(자기 출발자리 쪽)로 밀려 가며 작아지는 것도 그래서다.

## 4. 프로토콜 확장

`PublicGameState`에 일회성 채널 하나를 더한다. 모양과 쓰임새는 이미 있는 `lastThrow`와 같다.

```ts
lastMove: {
  /** 이 이동을 기록한 이벤트의 id. 연출을 한 번만 재생하는 열쇠. */
  eventId: string;
  /** 함께 움직인 말. 업힌 묶음이면 여럿이다. */
  pieceIds: string[];
  /** 떠난 칸. 출발 대기에서 나왔으면 null. */
  fromNodeId: string | null;
  /** 밟고 지나간 칸을 순서대로. 마지막이 도착 칸. */
  path: string[];
  /** 이 이동으로 잡힌 상대 말. */
  capturedPieceIds: string[];
} | null
```

### 4.1 서버가 이미 갖고 있는 값

- `MoveOption.traversed`: 밟은 칸 목록. `moveAlongRoute()`가 만들며 참으로 나면 마지막이 `FINISH`다.
- `movePieces()`의 반환값에 `capturedPieceIds`와 `movedPieceIds`가 있다.
- 이벤트 id는 `nextEvent()`가 `event-${events.length + 1}`로 붙인다. `resolveMove()`가 기록한 이동 이벤트의 id를 그대로 쓴다.

지금은 이 값들이 `resolveMove()` 안에서 쓰이고 버려진다. 새로 계산할 것은 없고, `GameState`에 담아 `toPublicGameState()`가 내보내게만 하면 된다. 시간 초과 자동 진행도 같은 리듀서를 지나므로 함께 따라온다.

잡힌 말의 색과 임자는 클라이언트가 `pieces`에서 id로 찾는다. 잡힌 말이 서 있던 칸은 도착 칸(`path`의 마지막)이므로 따로 담지 않는다.

### 4.2 되짚어 본 경계

- **재접속**: 스냅숏에 남아 있는 `lastMove`로 옛 연출이 튀지 않도록, 클라이언트는 처음 받은 eventId를 "이미 본 것"으로 심고 시작한다. `TurnPanel`이 던지기에 쓰는 방식과 같다.
- **다시 하기**: 새 게임의 이벤트 id는 `event-1`부터 다시 시작한다. 다만 다시 하기는 반드시 대기 국면을 지나므로 `GameScreen`과 무대가 언마운트되어 기억이 초기화된다. 옛 id와 겹쳐 연출을 건너뛰는 일은 생기지 않는다.
- **참으로 나기**: `path`의 마지막이 `FINISH`인데 이 칸은 판에 좌표가 없다. 시작점 모서리까지 밟아 간 뒤 그 자리에서 작아지며 사라지게 한다.
- **출발에서 나오기**: 서버는 `O0`을 기준으로 경로를 계산하므로 `fromNodeId`는 null이고 `path`는 `O1`부터 시작한다. 말은 판 밖 아래에서 첫 칸으로 올라온다.

## 5. 3D 장면

### 5.1 판

- 바탕: 한지 색 판에 얕은 테두리. 결은 캔버스로 그린 텍스처.
- 길: 판보다 조금 파인 음각 띠. 지름길 대각선도 같은 방식.
- 칸: 살짝 솟은 원반. 출발점은 주홍 고리와 진행 방향 살촉, 길목은 금색 고리와 겹살촉, 방은 금색 원반. 지금 CSS가 표현하는 강조를 그대로 옮긴다.
- 조명: 반구광 + 비스듬한 주광 하나. 주광만 그림자를 드리운다.
- 카메라: 정사 투영, 판을 수직으로 내려다본다(3.1 참고).

### 5.2 말

낮고 둥근 조약돌. 편 색과 무늬는 지금 팔레트를 그대로 쓴다. 업힌 묶음은 조금 더 두껍게 하고 그림자를 키워 무게를 준다(개수는 DOM 글자가 읽는다).

### 5.3 편 색 한 곳 모으기

편 색이 지금 `globals.css`에만 있어 3D가 쓸 수 없다. 색값을 `client/sideColor.ts`로 옮겨 단일 출처로 삼고, **CSS의 색값이 그것과 어긋나면 실패하는 단위 테스트**를 붙여 두 곳이 갈라지는 것을 막는다.

## 6. 연출

한 이동은 큐에 담긴 단계들로 재생한다.

1. **밟아 가기** — `path`를 따라 칸당 약 110ms, 칸마다 살짝 뛴다. 경로가 길면 칸당 시간을 줄여 **밟아 가기 전체가 900ms를 넘지 않게** 한다(모 다섯 칸이 550ms, 지름길을 포함한 가장 긴 경로도 이 상한 안에 든다). 빽도는 같은 코드로 뒤로 밟는다.
2. **충격** — 잡은 경우에만. 도착 칸에서 충격파 고리가 판을 따라 퍼지고 잦아든다.
3. **튕겨내기** — 잡힌 말이 하늘로 떴다가 호를 그리며 판 아래 출발자리 쪽으로 작아지며 사라진다. 사라진 뒤에는 DOM 출발 칸에 그 말이 나타나 있다.

연출은 권위 있는 상태를 바꾸지 않는다. 어떤 단계에서 멈추더라도 마지막 자리는 서버가 준 자리와 정확히 같다. 연출 중에도 DOM 버튼은 이미 도착 칸에 있으므로 조작이 막히지 않는다.

DOM 글자는 3D 말과 함께 걸어갈 수 없다. 그래서 움직이는 묶음과 잡힌 말의 버튼 글자는 연출이 도는 동안 숨기고, 연출이 끝나면 도착 칸에서 다시 보이게 한다. 버튼 자체는 계속 그 자리에 있으므로 클릭과 스크린 리더는 영향을 받지 않는다.

`prefers-reduced-motion`이면 큐를 건너뛰고 결과 자리에 바로 놓는다. 연출이 도는 동안에만 프레임 루프를 돌리고, 끝나면 필요할 때만 그린다.

## 7. 모듈 경계

새로 만드는 것:

| 파일 | 책임 | 의존 |
| --- | --- | --- |
| `client/three/boardScene.ts` | 판·길·칸·조명·정사 카메라를 세우고 칸의 월드 좌표를 준다 | three를 인수로 받는다 |
| `client/three/piece.ts` | 말 형상과 편 색 재질, 묶음 두께 | three, `sideColor` |
| `client/three/moveAnimation.ts` | 이동 큐와 시간 계산(순수 함수) | 없음 |
| `client/components/BoardStage.tsx` | 캔버스, 렌더러, 리사이즈, React 접합 | 위 세 모듈 |

`boardScene`과 `moveAnimation`은 렌더러를 만지지 않고 three를 인수로 받으므로 Node에서 검증할 수 있다. `yutStick.ts`와 `YutSticks.tsx`가 이미 같은 방식으로 나뉘어 있다.

고치는 것: `shared/protocol.ts`, `server/game/types.ts`, `server/game/reducer.ts`, `client/components/YutBoard.tsx`, `client/sideColor.ts`, `app/globals.css`.

## 8. 검증

- **서버 단위**: 잡기 있는 이동, 평범한 이동, 빽도, 출발에서 나오기, 참으로 나기가 각각 올바른 `lastMove`를 남기는지. 업힌 묶음이 `pieceIds`에 모두 담기는지. 자동 진행도 같은 값을 남기는지.
- **3D 수학(Node)**: 칸의 월드 좌표가 퍼센트 좌표와 일치하는지, 정사 절두체가 판을 정확히 담는지(3.1의 항등 사상 검증), 이동 애니메이션이 마지막 프레임에서 권위 있는 자리와 정확히 같아지는지, 경로가 길어도 전체 시간이 상한을 넘지 않는지.
- **팔레트**: `sideColor.ts`의 색값이 `globals.css`에 그대로 있는지.
- **UI(jsdom)**: WebGL이 없을 때 3D 클래스가 붙지 않고 2D 판이 그대로 나오는지. 기존 보드 테스트 10개는 수정 없이 통과해야 한다.

## 9. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 3D와 DOM의 자리가 어긋난다 | 수직 정사 투영으로 항등 사상을 만들고 테스트로 고정한다 |
| 연출이 권위 있는 상태와 어긋난다 | 연출은 표현만 하고, 마지막 자리는 항상 서버 값. 끝 상태 일치를 테스트한다 |
| 긴 경로에서 연출이 늘어진다 | 칸당 시간을 줄여 전체 시간에 상한을 둔다 |
| 접근성 후퇴 | 조작과 라벨을 DOM에 그대로 두고, 캔버스는 `aria-hidden` |
| WebGL 없는 환경 | 클래스가 붙지 않아 2D 판으로 동작. 컨텍스트를 잃으면 되돌린다 |
| 편 색이 CSS와 갈라진다 | 단일 출처 + 어긋나면 실패하는 테스트 |
